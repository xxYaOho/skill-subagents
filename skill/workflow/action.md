# Workflow: 行动 ↔ 确认 → 完成

适用场景：直接给出一个目标或现象（比如"定位某个问题"、"调研某件事"），没有先形成草案，由 agent 自主判断该派遣什么子代理、是否需要复核。

本文件的每一步都在实例化 `SKILL.md` 中定义的飞轮原语（产出 → 验证 → 修正 → 再验证 → 停止，单次最多修正 10 轮）。下文在每一步标注它对应飞轮的哪一次运行、修正条件和停止条件，而不是抽象引用。

## 1. 规划

了解目标后，根据工作单元数量选择单体、普通并行或蜂群，并根据子代理职责进行组合。

## 2. 飞轮

先执行直接验证，再根据未覆盖风险决定是否监察。

**这是飞轮的一次运行**：产出 = 子代理返回的结论或变更；验证 = 直接验证优先，未覆盖风险再追加监察；修正 = 把审查缺陷转给原产出方修正后再次提交验证；停止条件 = 直接验证足以覆盖主要风险且满足验收标准，或剩余风险对应的监察返回 `STATUS: PASS`。

- 结论类产出：证据不能自证、或结论将被传播为决策依据时，派遣 `critic-strict` 检查证据与推理链；证据自含可核验、采纳代价可逆的终态结论，不追加监察。
- 行动类产出：先运行测试、构建、真实渲染或其他直接验证；仍有忠实度、回归、契约或隐藏正确性风险时，派遣 `critic-gate`。
- 飞轮期间，具体工作在子代理之间，Orchestrator 负责补充和传递信息，例如把审查缺陷转给原产出方修正后再次提交验证。
- 修正轮次不超过 10 轮；达到上限后停止并告诉用户具体情况。
- 直接验证足以覆盖主要风险且满足验收标准，或剩余风险对应的监察 PASS 后停止；随后汇总结果向用户汇报，等用户确认。
